# Activity post reference UI

The user supplied four visual references and explicitly requested their composer, document rows and single/multiple-photo presentation. Use these references as the approved design. Changes are limited to activity posts; discussion/comment/reply markup, controls, styles and behavior remain as they are. Preserve the currently verified shared attachment flow, its identity/size fixes, file limits, private fetching and saved-post retry behavior.

The composer has separate Photo and Document buttons feeding the same selected-file queue and existing flow. Photo chooses supported raster images; Document remains a general file chooser. Show Attached plus the file count and compact removable chips above the action row. Chips have a colored type badge, filename and size/upload status. Photo/Document sit left; Post Activity sits right; the existing community visibility and limits appear beneath. Retain drafts when cancelled and disable both pickers/removal while saving or retrying an uncertain outcome.

Posted cards use the reference's avatar/name/timestamp arrangement and green left border. A single photograph fills a rounded image tile with download and filename/size overlays. Two photographs appear side by side. Three or more use a three-tile collage: one large tile and two smaller tiles, with +N on the last tile for additional photographs. A caption shows the true photo count and combined size. Clicking any tile opens the full-size viewer, including previous/next and keyboard navigation through all photographs. Fetch only visible tile content initially; reuse in-flight/cached private content when opening a preview.

Documents are compact rows with PDF/XLSX/DOCX/TXT or generic badges, the actual filename, type and formatted byte size. PDFs have Preview and Download; other formats have Download. PDF content loads on demand into an accessible preview dialog rather than an always-visible iframe. Page counts are omitted because the existing flow does not supply them. Preserve trusted MIME handling and never create public SharePoint links.

Viewer behavior: named modal dialog, contained keyboard focus, Escape/Close, focus return, correctly typed private Blob content, and independent read/download errors with retry. Abort obsolete requests; revoke each owned Blob URL on close/unmount. Preview/download actions share a bounded per-post/file cache rather than duplicate the same flow read. A stale aborted request must never change newer request state.

Keep the existing portal typography and palette: dark green actions/accent, mint image/selection accents, pale borders, and type-specific pastel badges. Scope new CSS to the activity composer/post/media/document/viewer. Test mobile stacking and long filenames. No comments, flow definitions, authorization, data schema, meeting-report attachments, or global theme changes.

Validation covers separate chooser controls sharing one queue, chips above actions, cross-picker limits, saved-post retry, lazy PDF previews, all gallery sizes and hidden-photo navigation, private fetch reuse, cleanup and keyboard focus. Run the relevant activity/comment regression tests, full frontend suite/build, desktop/mobile browser and accessibility checks, then publish to the same already-authorized Test/UAT site using fresh code-site metadata and read back exact assets/protected metadata.
